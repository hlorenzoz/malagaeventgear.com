## Phase 1: skeleton and toolchain

Governed by **Stack** and **Commands**.

Initialize the SvelteKit project with the pinned versions. Install with bun only. Write `package.json`,
`svelte.config.js`, `vite.config.ts`, `tsconfig.json`, `wrangler.toml`, `.gitignore`, `.prettierrc`, a
`Justfile` whose recipes are exactly the Commands table, and `.pre-commit-config.yaml` for Prettier and
whitespace. Write `.prettierrc` before the formatter runs once, for the reason given in **Conventions**.

Two details in **Stack** are the whole point of this phase. The build and check scripts run `wrangler types`
first and then the patch script, in that order, before anything else. Write `scripts/fix-types.ts` so it is
idempotent and safe on a repo where the type file does not exist yet. And `svelte.config.js` sets runes mode
scoped to exclude `node_modules`.

`.gitignore` must ignore the three foreign lockfiles by name, and `bun.lock` must be committed.

Prove this phase: `just check` passes on an empty project.

## Phase 2: single sources of truth

Governed by **Single sources of truth** and **Project defaults**.

Write `src/lib/data/site.ts` with the identity object in the structured shape that section mandates, plus its
derived helpers. Write `src/lib/data/packages.ts` with a small Zod validated catalog of three entries and its
full derived pricing API. Write `src/lib/utils/schema.ts` with the JSON-LD builders, one `#organization` node,
and the date normalizer.

Then write the guards, before the pages that could violate them. `no-duplicated-facts.test.ts` derives its
forbidden patterns from `siteConfig` and the catalog at test time, so it never needs editing when a field is
added. `sitemap-freshness.test.ts` fails on any route or catalog entry with no declared date. Both read source
with `import.meta.glob` and `?raw`, never `node:fs`.

Prove this phase: `just test` passes, and it fails if you temporarily paste a literal address into a component.
