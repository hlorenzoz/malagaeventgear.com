# post-no-csr: blog posts without hydration (Astro-like performance on SvelteKit)

Objective: ship zero SvelteKit JS on blog post pages (`csr = false`) while every interactive piece keeps working through one small vanilla script. Branch: `feat/i18n` (local commits only, never push). Delivery: single PR slice, work-unit commits. Test runner: Playwright (`bunx playwright test`, dev server on 5173) and Vitest (`bun run test`); prod checks with `playwright.prod.config.ts` (build + preview on 4173).

## Specs

- **S1. No hydration on posts.** `export const csr = false` in `src/routes/(public)/blog/[slug]/+page.ts`. Every post page in the 13 locales (today 1,157 HTML files: 89 posts x 13, news included) is served with no SvelteKit JS (`/_app/immutable/entry|chunks|nodes/*.js`, no `modulepreload`). The `<head>` stays identical: canonical, hreflang, Open Graph and every JSON-LD block (measured parity on 2026-11-15: 1 / 43 / 23 / 5).
- **S2. One enhancement script, loaded only on direct loads of a post.** Plain JS file (no imports, no framework), emitted by Vite as a hashed, non inlined asset (`?url&no-inline`, to verify in the build: Vite inlines small `?url` assets otherwise). Injected in the post `<head>` through `{@html}` (SvelteKit docs: with `csr = false` "`<script>` tags inside all Svelte components are removed"; `{@html}` scripts survive, as the JSON-LD proves). The same markup reaches a post opened by client side navigation (verified: from `/blog/` SvelteKit 2.70 navigates into a `csr = false` post without a reload), where the script must NOT execute and the Svelte handlers keep working. The script registers NO service worker: no page of the site registers one today (corrected in L7, the original premise was false).
- **S3. Header (`TopNavBar.svelte`, shared by the whole site).**
  - Theme toggle works on a post without JS from SvelteKit: flips `data-theme` on `<html>`, writes `localStorage` key `theme` (same key the inline script in `src/app.html` reads), and the button shows the right icon. Both icons are always in the HTML and CSS picks one, because today the icon is an `{#if}` on client state.
  - Mobile menu works on a post: the panel is always in the HTML (hidden), the button has `aria-expanded` and `aria-controls`, and the script toggles them. Do NOT use the Popover API (Baseline newly available only since 2025-01-27, iOS 18.3).
  - Hide on scroll down / show on scroll up on posts keeps working.
  - Every other page of the site behaves exactly as before (same visible result, same tests green).
- **S4. Post interactions** keep working on a direct load: copy link (both buttons) and the sharing options menu (`ShareThis.svelte`), the sticky share bar visibility (`BlogPost.svelte` `onMount`), ClickToTweet on text selection (`ClickToTweet.svelte`), and the active section highlight of the table of contents (`TableOfContents.svelte`).
- **S5. Reviews on posts** (`Testimonials.svelte`, `TestimonialCard.svelte`): "Read more" / "Read less" expands a long review (today, without JS, a long review stays clamped to 4 lines and the button does nothing, so content is hidden), and the carousel arrows appear and scroll when the track overflows. Labels stay in the page language (`i18n.t.testimonials.readMore` / `readLess`). Reviews are never translated.
- **S6. Gallery carousel (`ImageMarquee.svelte`).** The 507 posts whose carousel is server rendered (`deferMount={false}`) keep working as today. The 429 deferred ones must not stay empty on a direct load: the track markup is in the HTML inside a `<template>` and the script mounts it when the carousel nears the viewport (keeps the reason for deferring: no 60 images painted in the critical window). Translated `alt` text stays per locale (`galleryAlt`).
- **S7. Tests.** One RED test per rule before the fix, then GREEN. Direct load and client side navigation are both covered for S3 to S6. Existing specs that touch these pieces (`share.spec.ts`, `click-to-tweet.spec.ts`, `blog-marquees.spec.ts`, `i18n.spec.ts`, `gallery-alt.prod.spec.ts`) stay green, adapted only where the change requires it. A test asserts a post ships no SvelteKit JS. A test asserts the enhancement script does not run after client side navigation.
- **S8. Measurement** (CLAUDE.md rule 10): mobile Lighthouse before/after on `/blog/audio-visual-rental-for-conferences/` and one translated post, 3 runs each; `bunx @lhci/cli autorun` before closing. Baseline 2026-11-15 (local preview, 3 runs): score 81/81/82, FCP 2.7 to 2.9 s, LCP 4.1 to 4.2 s, JS 189 KiB in 32 requests. Experiment with csr=false alone: 97/97/97, FCP 0.9 s, LCP 2.6 s, 0 JS.
- **S9. Docs.** `.agents/CHANGELOG.md` entry, and `CLAUDE.md` documents the rule: a post is not hydrated, interactive behaviour on a post lives in the enhancement script and in SSR markup.
