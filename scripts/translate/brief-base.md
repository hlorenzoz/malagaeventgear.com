## Language rules
- Register: fr vous, it tu, de Sie, nl je, pt-pt formal third person (o seu, contacte-nos), pt-br você (seu, entre em contato), sv/da/nb du, zh 您.
- Variants: pt-pt and pt-br are separate texts with their own vocabulary (ecrã/tela, equipa/equipe, telemóvel/celular, contacto/contato). zh-hans simplified and Mainland terms, zh-tw traditional and Taiwan terms, zh-hk traditional written standard Chinese with Hong Kong terms (never Cantonese colloquial such as 嘅 咗 喺 啲 冇 係). nb is Bokmål, never Danish spellings.
- Sentence case in headings for every language except English (no Title Case).
- Rule 12: ASCII punctuation only (straight quotes and apostrophes, no em or en dash, no one character ellipsis, no non breaking space, no semicolons in prose, no English style hyphenated compounds, hyphens only where the language's spelling requires them). Chinese uses full width Chinese punctuation, but no doubled em dash (U+2014 twice) and no doubled ellipsis (U+2026 twice), stricter than CLAUDE.md on purpose because they are em dash and ellipsis lookalikes. Carve outs that are language and not decoration: Dutch and German spelling hyphens (see the lessons below), and brand or model names that carry a hyphen.
- Natural, idiomatic, publishable copy. Rewrite machine sounding sentences. Consistent terminology within each locale and with the site's existing translations.

## Tools (repo scripts, use them, do not rewrite them)
- `just post-translate-check {slug}` checks all 12 files: frontmatter keys, `sourceUpdated`, title and description length, forbidden characters, semicolons, Cantonese and simplified leaks, structure parity with the English (headings, links, numbers, images, table rows, quotes), the keyword (collisions with every other keyword of the locale, count in the body) and the slug. It must print ALL OK. Under the table it lists warnings that do not fail the check but that you must clear or justify in your report: the keyword not in the first paragraph, used fewer than 2 times in the body or not verbatim in the title (the lessons below require all three), and single digit numbers that differ from the English (fine when the English digit is spelled out in words, say so). `--strict` turns those warnings into failures. A `Cantonese` or `simplified` finding, a title or description over the limit, a `numbers differ` or `links differ` line are always real problems to fix. After `bun run build`, `just post-translate-check {slug} --post-build` also audits the in-page anchors of the built pages and says NEEDS BUILD when the build is older than the files.
- `just post-translate-map {slug} --map <json file>` inserts the 12 content map entries from a JSON file shaped `{ "fr": { "slug": "...", "keyword": "..." }, "it": { ... } }` (status is always `propuesta`). It refuses a duplicate key and a slug or keyword already used in that locale. Keep the JSON in the scratchpad directory.
- `bun scripts/translate/status.ts` lists which translations are missing or stale.
- You do NOT run `just post-translate-finish`: the orchestrator does (tests, build, sitemaps, local commit).
